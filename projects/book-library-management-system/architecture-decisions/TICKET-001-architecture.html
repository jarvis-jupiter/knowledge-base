TICKET-001: Book Library Management System

Ticket ID: TICKET-001 Date: 2026-03-12 Architect: Architect Agent Status: Awaiting Approval

1. Overview

A full-stack, web-based library management system with two user roles (librarian, member), a RESTful JSON API backend, and a lightweight server-rendered HTML frontend. The system manages a catalogue of books and tracks borrow/return circulation.

4. Data Model (Prisma Schema)

// prisma/schema.prisma

datasource db {
  provider = "sqlite"           // override to "postgresql" via env
  url      = env("DATABASE_URL")
}

generator client {
  provider = "prisma-client-js"
}

model User {
  id             Int      @id @default(autoincrement())
  email          String   @unique
  passwordHash   String
  role           Role     @default(MEMBER)
  name           String
  membershipNumber String? @unique  // null for librarians
  createdAt      DateTime @default(now())

  loans          Loan[]
}

enum Role {
  LIBRARIAN
  MEMBER
}

model Book {
  id        Int      @id @default(autoincrement())
  title     String
  author    String
  isbn      String   @unique
  genre     String
  quantity  Int      @default(1)  // total copies owned
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  loans     Loan[]
}

model Loan {
  id           Int       @id @default(autoincrement())
  book         Book      @relation(fields: [bookId], references: [id])
  bookId       Int
  member       User      @relation(fields: [memberId], references: [id])
  memberId     Int
  borrowedAt   DateTime  @default(now())
  dueDate      DateTime
  returnedAt   DateTime?
  status       LoanStatus @default(ACTIVE)
}

enum LoanStatus {
  ACTIVE
  RETURNED
}

Derived field: availableCopies
Not stored. Computed at query time as:

availableCopies = book.quantity - COUNT(loans WHERE bookId = book.id AND status = 'ACTIVE')

This is done in the service layer (not in the DB schema) to avoid stale denormalised data.

5. REST API Contract

All endpoints return JSON when called with Accept: application/json; otherwise they redirect to the server-rendered view. This dual-mode pattern lets the Nunjucks frontend and any future SPA share the same routes.

5.1 Authentication

MethodPathRoleDescription
GET/loginPublicRender login form
POST/loginPublicAuthenticate; set session cookie
POST/logoutAuthenticatedDestroy session

Session payload stored server-side:

{ "userId": 1, "role": "LIBRARIAN" }

5.2 Books

MethodPathRoleDescription
GET/booksLIBRARIANList all books (paginated, 20/page)
GET/books/newLIBRARIANRender add-book form
POST/booksLIBRARIANCreate book
GET/books/:id/editLIBRARIANRender edit form
PUT/books/:idLIBRARIANUpdate book
DELETE/books/:idLIBRARIANDelete book (blocked if active loans)

POST /books body:

{
  "title": "string, required",
  "author": "string, required",
  "isbn": "string, required, unique",
  "genre": "string, required",
  "quantity": "integer ≥ 1, required"
}

Error responses:

  • 409 Conflict — duplicate ISBN
  • 422 Unprocessable — validation failure (missing fields, quantity < 1)
  • 400 Bad Request — delete blocked due to active loans (body: { "error": "Book has active loans and cannot be deleted." })

5.3 Members

MethodPathRoleDescription
GET/membersLIBRARIANList all members
GET/members/newLIBRARIANRender registration form
POST/membersLIBRARIANRegister member

POST /members body:

{
  "name": "string, required",
  "email": "string, required, unique",
  "membershipNumber": "string, required, unique",
  "password": "string, required, min 8 chars"
}

Error responses:

  • 409 Conflict — email or membershipNumber already in use

5.4 Loans

MethodPathRoleDescription
POST/loansLIBRARIANCreate loan (borrow)
PATCH/loans/:id/returnLIBRARIANRecord return
GET/loans/overdueLIBRARIANList all overdue loans

POST /loans body:

{
  "bookId": "integer, required",
  "memberId": "integer, required"
}
  • dueDate is set to now + 14 days server-side — not accepted from client.
  • 409 Conflict if availableCopies == 0.

GET /loans/overdue response:

[
  {
    "loanId": 5,
    "memberName": "Jane Doe",
    "bookTitle": "Dune",
    "dueDate": "2026-02-26",
    "daysOverdue": 14
  }
]

5.5 Catalogue (search)

MethodPathRoleDescription
GET/catalogue?q=<string>Authenticated (any role)Search books
  • Matches title, author, or genre via case-insensitive LIKE '%q%'.
  • Response includes: id, title, author, genre, availableCopies.
  • Returns [] (empty array) with HTTP 200 when no results.

5.6 Member Dashboard

MethodPathRoleDescription
GET/dashboardMEMBERView own active loans

Response per loan: bookTitle, borrowedAt, dueDate, daysRemaining.
daysRemaining is computed as floor((dueDate - now) / 86400000) — may be negative for overdue loans shown in dashboard (displayed in red).

6. Authentication & Authorisation

  • Session store: in-memory for development; connect-pg-simple in production (same Postgres DB).
  • Session cookie: httpOnly: true, sameSite: 'lax', secure: true in production.
  • Password hashing: bcrypt.hash(password, 12) on registration/seed; bcrypt.compare on login.
  • Middleware:
    • requireLogin — redirects to /login if no session.
    • requireRole('LIBRARIAN') — returns 403 if logged-in user is not a librarian.
  • Librarians can access all routes. Members can only access /catalogue, /dashboard, and auth routes.

8. Validation Rules (Server-side)

All validation is performed in route handlers before database calls. Use a lightweight schema validator (e.g., zod or manual checks — Dev decides).

FieldRule
isbnExactly 10 or 13 digits (strip hyphens before check)
quantityInteger, 1–999
emailBasic RFC 5322 regex
passwordMin 8 characters
membershipNumberAlphanumeric + hyphens, 3–20 chars
All string fieldsNon-empty, max 255 chars

9. Error Handling

  • All unhandled errors go through a central Express error handler that returns { "error": "message" } JSON or renders an error page.
  • 404 — unknown route → 404.njk / JSON { "error": "Not found" }.
  • 500 — unexpected server error → generic message (never expose stack traces in production).
