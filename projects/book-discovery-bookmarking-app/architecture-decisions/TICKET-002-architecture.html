1. Overview

This document defines the full technical architecture for the Book Discovery & Bookmarking application. Authenticated users can search for books via the Google Books API and save books to a personal bookmark list.

Covers: technology stack, system topology, data model, REST API contract, Google Books integration, authentication approach, folder structure, and a full acceptance-criteria → design-component mapping.

4. Data Model

4.1 users Table

model User {
  id           String     @id @default(uuid())
  email        String     @unique
  passwordHash String
  createdAt    DateTime   @default(now())
  bookmarks    Bookmark[]
}

4.2 bookmarks Table

Stores a snapshot of Google Books metadata at bookmark time. This allows the bookmark list to render without a live API call on every page load — tolerant of future Google Books changes.

model Bookmark {
  id             String   @id @default(uuid())
  userId         String
  googleVolumeId String
  title          String
  authors        Json     @default("[]")   // string[]
  thumbnailUrl   String?
  description    String?
  bookmarkedAt   DateTime @default(now())
  user           User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@unique([userId, googleVolumeId])   // DB-level idempotency guarantee
}

Key decisions:

  • @@unique([userId, googleVolumeId]) enforces idempotency at the DB level — no duplicate bookmarks even under concurrent requests (AC 4b)
  • authors stored as JSONB array — avoids a junction table for MVP
  • thumbnailUrl and description nullable — Google Books may not provide them (AC 7b)

5. API Contract

Base URL: /api  |  Content-Type: application/json  |  Auth: httpOnly JWT cookie (token)

5.1 Auth Endpoints

POST /api/auth/register

Request: { "email": "user@example.com", "password": "mypassword" }

201 Created — sets token cookie, returns { "user": { "id": "...", "email": "..." } }

400 Bad Request — { "error": "Password must be at least 8 characters" }

409 Conflict — { "error": "Email already in use" }

Maps to AC 1

POST /api/auth/login

Request: { "email": "user@example.com", "password": "mypassword" }

200 OK — sets token cookie, returns { "user": { "id": "...", "email": "..." } }

401 Unauthorized — { "error": "Invalid email or password" } (intentionally ambiguous per AC 2b)

Maps to AC 2

POST /api/auth/logout

No request body. Clears token cookie.

200 OK — { "message": "Logged out" }

Maps to AC 8

5.2 Book Endpoints (Google Books Proxy)

The backend proxies all Google Books calls to keep the API key server-side and centralise error handling.

GET /api/books/search?q=<query>

Proxies: https://www.googleapis.com/books/v1/volumes?q=<query>&maxResults=20&key=API_KEY

Auth required.

{
  "results": [
    {
      "volumeId": "abc123",
      "title": "Clean Code",
      "authors": ["Robert C. Martin"],
      "description": "A handbook of agile software craftsmanship...",
      "thumbnailUrl": "https://books.google.com/...",
      "publisher": "Prentice Hall",
      "publishedDate": "2008-08-01",
      "pageCount": 431,
      "categories": ["Computers"]
    }
  ],
  "totalItems": 42

400 — missing q  |  401 — not authenticated  |  502 — Google Books unavailable → { "error": "Book search temporarily unavailable" }

Maps to AC 3

GET /api/books/:volumeId

Proxies: https://www.googleapis.com/books/v1/volumes/:volumeId?key=API_KEY

Auth required. Returns same shape as above but with full description.

404 — volume not found  |  502 — API error

Maps to AC 7

5.3 Bookmark Endpoints

GET /api/bookmarks

Auth required. Returns all bookmarks for the authenticated user.

Maps to AC 5

POST /api/bookmarks

Auth required.

{
  "googleVolumeId": "abc123",
  "title": "Clean Code",
  "authors": ["Robert C. Martin"],
  "thumbnailUrl": "https://...",
  "description": "..."

6. Authentication Design

Register / Login │ ▼ Backend validates credentials (Zod + bcrypt.compare) │ ▼ Generate JWT { userId, email } exp: 7 days │ ▼ Set-Cookie: token=<jwt>; HttpOnly; SameSite=Strict; Secure; Path=/; Max-Age=604800 │ ▼ Browser stores cookie automatically (no JS access — XSS-safe) │ ▼ All subsequent requests to /api/* include cookie automatically │ ▼ verifyToken middleware: 1. Extract token from req.cookies.token 2. Verify JWT signature (process.env.JWT_SECRET) 3. Attach decoded { userId } to req.user 4. Call next() or return 401

Route protection:

  • Backend: verifyToken middleware on all /api/books/* and /api/bookmarks/* routes.
  • Frontend: <RequireAuth> HOC wraps protected routes — redirects to /login if unauthenticated.
  • AC 9: Covered by both backend middleware (API level) and frontend route guard (UX level). Users can only query their own bookmarks — all queries are filtered by userId from JWT.

7. Google Books API Integration Pattern

Frontend (search page) │ GET /api/books/search?q=<query> ▼ BookService.search(query) on backend: 1. Encode query: encodeURIComponent(query) 2. Fetch: GET https://www.googleapis.com/books/v1/volumes ?q=<encoded>&maxResults=20&key=${GOOGLE_BOOKS_API_KEY} 3. On success → normalize response to internal BookResult shape 4. On network/5xx error → throw GoogleBooksApiError → return 502 5. On empty items → return { results: [], totalItems: 0 } │ ▼ BookService.normalize(item): - volumeInfo.imageLinks.thumbnail → thumbnailUrl (null if absent) - volumeInfo.authors → authors ([] if absent) - volumeInfo.description → truncate to 200 chars for search results - Full description returned on /api/books/:volumeId - Any missing field → null / omitted (no "undefined" labels) │ ▼ Normalized BookResult[] → JSON response to frontend

API Key: Stored in GOOGLE_BOOKS_API_KEY env variable. Backend logs a warning on startup if absent (falls back to keyless — 1000 req/day limit).
