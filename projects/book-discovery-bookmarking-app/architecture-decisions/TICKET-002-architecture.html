Key topology note: The Remix app is a Node.js server. Loaders and actions run on the Remix server and call the Express API via HTTP using a stored JWT bearer token (retrieved from the Remix session). The browser never makes direct API calls — all data flows through Remix loaders/actions.

4. Data Model

4.1 users Table

CREATE TABLE users (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email        TEXT UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  created_at   TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

Prisma Schema:

model User {
  id           String     @id @default(uuid())
  email        String     @unique
  passwordHash String
  createdAt    DateTime   @default(now())
  bookmarks    Bookmark[]
}

4.2 bookmarks Table

Bookmark storage stores the Google Books volume ID plus the essential display metadata (title, authors, thumbnail). This allows the bookmark list to render without a live API call on every page load — a key spec decision from TICKET-002 Rationale.

CREATE TABLE bookmarks (
  id               UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id          UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  google_volume_id TEXT NOT NULL,
  title            TEXT NOT NULL,
  authors          JSONB NOT NULL DEFAULT '[]',   -- string[]
  thumbnail_url    TEXT,
  description      TEXT,
  bookmarked_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (user_id, google_volume_id)              -- idempotency constraint
);

Prisma Schema:

model Bookmark {
  id             String   @id @default(uuid())
  userId         String
  googleVolumeId String
  title          String
  authors        Json     @default("[]")
  thumbnailUrl   String?
  description    String?
  bookmarkedAt   DateTime @default(now())
  user           User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@unique([userId, googleVolumeId])
}

Key design decisions:

  • UNIQUE(user_id, google_volume_id) enforces idempotency at the DB level (AC 4: no duplicate bookmarks).
  • authors stored as JSONB array — avoids a junction table for MVP; sufficient for display.
  • thumbnail_url and description nullable — Google Books may not provide them (AC 7: graceful omission).

5. API Contract

Base URL: /api  |  Content-Type: application/json

Auth: Authorization: Bearer <jwt> header. Remix loaders/actions attach this header using the JWT stored in the Remix session cookie (server-side only — never exposed to the browser).

6. Authentication Design

6.1 Flow

Register / Login (browser submits Remix <Form>) │ ▼ Remix action runs server-side │ ▼ Remix action calls POST /api/auth/register or /login (Express) │ ▼ Express validates credentials → returns { token, user } │ ▼ Remix action stores token in Remix session: session.set("token", token) session.set("userId", user.id) Set-Cookie: __session=<signed-session>; HttpOnly; SameSite=Lax; Secure; Path=/ │ ▼ Browser stores signed session cookie automatically (no JS access — XSS safe) │ ▼ Subsequent Remix loaders/actions: 1. Read session from cookie: await getSession(request.headers.get("Cookie")) 2. Extract token: session.get("token") 3. Attach to backend call: Authorization: Bearer <token> 4. If no token → redirect to /login

6.2 Route Protection

Backend: verifyToken middleware applied to all /api/books/* and /api/bookmarks/* routes. Validates Bearer token from Authorization header.

Frontend (Remix): Each protected loader checks the session for a valid token via a requireUserSession(request) helper. If absent, it throws redirect("/login"). This provides both UX-level and server-level protection in one place — no separate route guard component needed.

AC 9 (Access control): Covered by backend middleware (API-level) and Remix loader guards (render-level). Unauthenticated requests are redirected before any data is fetched.

7. Google Books API Integration Pattern

Browser navigates to /search?q=clean+code │ ▼ Remix loader (search.tsx) — runs server-side: 1. requireUserSession(request) → get token 2. Extract q from new URL(request.url).searchParams 3. Call GET /api/books/search?q=<query> with Bearer token │ ▼ Express BookService.search(query): 1. encodeURIComponent(query) 2. GET https://www.googleapis.com/books/v1/volumes?q=<encoded>&maxResults=20&key=${KEY} 3. On success: normalize → BookResult[] 4. On error: throw GoogleBooksApiError → 502 5. On empty: return { results: [], totalItems: 0 } │ ▼ Remix loader returns normalised data → component renders via useLoaderData() No client-side fetch; no loading spinners from data layer

Transformation layer (bookService.normalize):

  • Maps volumeInfo.imageLinks.thumbnail → thumbnailUrl (null if absent)
  • Maps volumeInfo.authors → authors (empty array if absent)
  • Truncates description to 200 chars for search results (AC 3b)
  • Full description returned on detail endpoint
  • Any missing field → null / omitted gracefully (AC 7b)

9.2 Test-Driven Development (TDD) — First-Class Constraint

TDD is mandatory at all layers. This is not an afterthought — it is the primary development workflow.

The rule: A failing test must be written before any implementation code. A feature is not considered done until all its tests pass.

This applies to:

  • Unit tests (Vitest): pure functions in services/, utils/, and transforms.ts
  • Integration tests (Vitest + Supertest): Express route handlers calling a test database
  • E2E tests (Playwright): full user journey against a running app (see Section 11)

TDD workflow per feature:

  1. Read the AC for the feature from TICKET-002.md
  2. Write a failing test that encodes the AC
  3. Write the minimum implementation to make the test pass
  4. Refactor (clean up, extract helpers) — tests must remain green
  5. Repeat for the next AC

No feature is mergeable with a failing test. CI must run all tests on every PR; the PR gate blocks merge on any failure.

10. Functional Programming Constraints

These constraints apply to both the frontend (Remix routes, components, utils) and the backend (Express services, route handlers).

10.1 Pure Functions

Every business logic function must be pure: given the same input, it always returns the same output, and it has no side effects.

// ✅ Pure — always same output for same input, no side effects
const truncateDescription = (desc: string, maxLength: number): string =>
  desc.length <= maxLength ? desc : `${desc.slice(0, maxLength)}...`;

// ❌ Impure — reads external state, mutates
const truncateDescription = (desc: string): string => {
  config.lastTruncated = desc; // side effect
  return desc.slice(0, globalMaxLength); // reads external state
};

10.2 Composition Over Inheritance

Build complex logic by composing small, single-purpose functions. Do not use classes with inheritance hierarchies in business logic.

// ✅ Composed from small pure functions
const normalizeBook = (volume: GoogleBooksVolume): BookResult => ({
  volumeId: extractVolumeId(volume),
  title: extractTitle(volume),
  authors: extractAuthors(volume),
  thumbnailUrl: extractThumbnailUrl(volume),
  description: truncateDescription(extractDescription(volume), 200),
});

10.3 Immutability

Never mutate objects or arrays. Use spread, map, filter, and reduce for all transformations.

// ✅ Immutable
const addBookmark = (bookmarks: Bookmark[], newBookmark: Bookmark): Bookmark[] =>
  [...bookmarks, newBookmark];

const removeBookmark = (bookmarks: Bookmark[], volumeId: string): Bookmark[] =>
  bookmarks.filter(b => b.googleVolumeId !== volumeId);

// ❌ Mutation
bookmarks.push(newBookmark);
bookmarks.splice(index, 1);

10.4 No FP Libraries

Use native TypeScript only. The following libraries are explicitly prohibited:

  • fp-ts
  • ramda
  • lodash/fp
  • sanctuary
  • Any other functional programming utility library

Native Array.prototype methods, Object.assign, spread syntax, and structuredClone are sufficient.

10.5 Side Effects at the Edge

Side effects (database calls, HTTP calls, session reads/writes, logging) must be isolated at the outermost layer and kept out of business logic functions.

LayerAllowedNot Allowed
Backend services/Pure logic, transformations, validation schemasPrisma calls, fetch, console.log
Backend route handlersPrisma calls, JWT verification, error responsesBusiness logic embedded directly
Frontend utils/transforms.tsPure transformation functionsfetch, session access
Frontend loaders/actionsfetch, session reads/writes, redirectsBusiness logic embedded directly
 
// ✅ Backend route handler (side effects here)
router.post("/bookmarks", verifyToken, async (req, res) => {
  const parsed = createBookmarkSchema.safeParse(req.body);
  if (!parsed.success) return res.status(400).json({ error: parsed.error });
  const bookmark = buildBookmark(req.user.userId, parsed.data); // pure fn
  const saved = await prisma.bookmark.upsert({ ... }); // side effect at edge
  res.status(201).json({ bookmark: saved });
});

// ✅ Pure service function (no side effects)
const buildBookmark = (userId: string, data: CreateBookmarkRequest): BookmarkCreateInput => ({
  userId,
  googleVolumeId: data.googleVolumeId,
  title: data.title,
  authors: data.authors,
  thumbnailUrl: data.thumbnailUrl ?? null,
  description: data.description ?? null,
});
